# Сервис корпоративных объявлений

Веб-приложение на Django для просмотра и администрирования корпоративных
объявлений. Данные приложения хранятся в SQLite-базе Django и описаны моделями
ORM. Предыдущие JSON- и SQLite-данные можно импортировать повторно.

## Возможности

- главная страница и подробный просмотр объявления;
- списки всех, активных на выбранную дату и архивных объявлений;
- поиск по заголовку, тексту и отделу;
- фильтрация по отделу, приоритету и статусу;
- сортировка по разрешённым полям и постраничная навигация;
- сводная статистика по объявлениям, отделам и приоритетам;
- создание, редактирование и удаление записей через Django Admin.

Требования о помещениях и бронированиях адаптированы к теме сервиса: вместо
помещений используются объявления, вместо бронирований — архив объявлений,
а поиск свободных объектов заменён фильтром активных объявлений по дате.

## Модели и база данных

Модели находятся в `portal/models.py`:

- `Department` — отдел компании с уникальным названием;
- `Announcement` — объявление с заголовком, текстом, отделом, приоритетом,
  датами публикации и окончания, а также статусом публикации.

`Announcement.department` — внешний ключ на отдел с `on_delete=PROTECT` и
обратным именем `announcements`. Миграции Django в `portal/migrations/`
создают и изменяют таблицы основной базы `db.sqlite3`.

Представления сайта в `portal/views.py` получают данные только через Django
ORM; прежние прямые SQL-запросы оттуда удалены. Файлы `sql/schema.sql`,
`sql/queries.sql` и модуль `db/` сохранены как материалы предыдущей
практической работы и не используются страницами приложения. Команда переноса
данных читает прежнюю SQLite-базу в режиме только для чтения и записывает
объявления в новую базу посредством ORM.

В представлениях применяются более 15 разных ORM-сценариев:

1. Получение списка и последних объявлений через `all()` и срез QuerySet.
2. Получение объявления по ID через `get_object_or_404()`.
3. Фильтр по одному условию — приоритету.
4. Фильтр по нескольким условиям — активные опубликованные объявления на дату.
5. Проверка существования отдела и фильтр объявлений по отделу.
6. Фильтры по статусу публикации и сроку действия.
7. Исключение текущего объявления через `exclude()` при показе материалов
   того же отдела.
8. Поиск по заголовку через `title__icontains`.
9. Поиск сразу по заголовку, тексту и названию отдела через `Q`.
10. Сортировка по одному полю — заголовку.
11. Сортировка по связанному отделу с дополнительной сортировкой по ID.
12. Загрузка отдела вместе с объявлением через `select_related()`.
13. Получение короткого списка отделов через `values()`.
14. Подсчёт общих показателей через `aggregate()`, `Count` и `Avg`.
15. Группировка по отделам через `annotate()` и `Count`.
16. Группировка по приоритету через `values()` и `annotate()`.
17. Постраничная выдача с `Paginator`; параметры поиска и сортировки
    сохраняются в ссылках.

Изменения объявлений и отделов доступны через Django Admin; модели также
проверяются тестами на создание, изменение, удаление и ограничения полей.

## Установка и запуск

В Windows PowerShell из каталога проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_legacy_announcements
python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Команда импорта повторно обновляет записи
по исходным ID. Для импорта из JSON укажите файл:

```powershell
python manage.py import_legacy_announcements --source data\announcements.json
```

Для управления объявлениями и отделами через интерфейс Django Admin создайте
администратора командой `python manage.py createsuperuser`, затем откройте
`/admin/`.

## Страницы и параметры

| URL | Назначение |
| --- | --- |
| `/` | Главная страница |
| `/announcements/` | Список с поиском, фильтрами, сортировкой и пагинацией |
| `/announcements/active/?date=YYYY-MM-DD` | Активные объявления на дату |
| `/announcements/archive/` | Архив опубликованных объявлений |
| `/announcements/<id>/` | Подробная страница и другие объявления отдела |
| `/statistics/` | Сводная статистика |
| `/admin/` | Создание, изменение и удаление записей |

Для списка поддерживаются параметры `q`, `department`, `priority`, `status`,
`sort` и `page`. Поля сортировки проверяются по списку допустимых значений;
при переходе между страницами поиск и фильтры сохраняются.

## Проверки

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py migrate
python manage.py test
python -m pytest -q
python -m flake8
```

Тесты проверяют модели, связи, импорт старых данных, ORM-фильтры и поиск,
сортировку, пагинацию, статистику, пустые результаты и некорректные параметры.
